## 1. Executive Summary

Me Arnaud Cheynut is an Avocat-Défenseur (full rights of audience before all Monégasque courts) practicing solo from 9 rue du Gabian, Monaco. His only digital footprint today is the Bar directory listing plus a shared email domain with Cabinet Zabaldano. This project delivers his first website — live at **arnaud-cheynut.com** — as a personal brand site: credibility signals a directory listing cannot carry, inbound lead capture for a bilingual FR/EN audience with geo-detected defaults (ADR-005), and content the lawyer updates himself through Supabase Studio without a developer in the loop. The Zabaldano affiliation appears only as factually accurate contact data; the brand identity is his alone (profile-master.md §3, §5; PROJECT-SUMMARY.md).

Success for a solo practitioner is specific: the phone rings with qualified inquiries, the site ranks for Monaco legal keywords within six months (500+ organic visits/month, 15+ form conversions/month, content-strategy.md §9), content updates take minutes rather than a support ticket, and annual running costs stay low (Vercel hosting, Supabase entry tier). The stack is locked by Human decision (ADR-002): Next.js 15 App Router, Supabase (Postgres, RLS, Storage), Vercel, Tailwind CSS with shadcn/ui, TypeScript strict. No external CMS enters the MVP scope; content lives in Supabase tables. Per Human direction (ADR-003, ADR-004), the site also delivers a dual-mode AI assistant — real-time voice plus streaming chat, scoped to administrative help (office information, navigation, process explanations) with a strict refusal of legal advice — and email touchpoints for every user-initiated process.

## 2. Core Workflows (The Happy Path)

*Source: content-strategy.md §3.1–§3.4; profile-master.md §2, §5; ADR-003 (lead/email flow), ADR-004 (AI assistant workflows).*

- **Inbound lead (FR/EN):** Monaco resident, international client, or corporate searches "avocat Monaco" or follows a referral → lands on Accueil in the locale matching their country (geo-detected; FR fallback for Monaco) → reads the value prop and trust signals → opens a practice area page with the process timeline → clicks "Prendre rendez-vous" / "Book a consultation" → fills the contact form → a Server Action validates the input with Zod → the row persists in `contact_submissions` first, so a failed email never loses a lead (ADR-003) → email notifications go out (form receipt to the visitor, notification to the lawyer; Resend by default, SMTP as the documented swap-in) → response within 24h ouvrées.
- **Urgent path (garde à vue, référés):** person in an emergency → persistent emergency banner visible on every page → taps the phone link (`tel:+37797980680`) → no form and no dead ends in this path.
- **Foreign lawyer / correspondent:** international counsel needing Monaco representation → À Propos page (network & correspondents section) → direct email or phone.
- **Lawyer publishes an actualité:** drafts in Supabase Studio (`posts`, status=draft) → legal self-review → sets status=published → static/ISR regeneration serves the page → sitemap and Article JSON-LD update.
- **Lawyer edits evergreen content:** practice area description, fee philosophy, or site settings (phone, hours, banner) → edits a row in Supabase Studio → the change propagates after revalidation.
- **Credential verification:** visitor checks the Bar registration number, RCP insurance mention, languages (FR/EN/IT), and office address → verifiable items only, no generic badges.
- **Lead triage:** lawyer opens `contact_submissions` in Supabase Studio → marks rows new/read/archived → attachments, if any, via private Storage signed URLs.
- **AI assistant — chat (new in v2, ADR-004):** visitor opens the site-wide widget → a visible disclaimer states the assistant provides administrative help only and that legal advice comes from Me Cheynut alone → the visitor asks about office information, navigation, practice-area summaries, or process explanations → the reply streams from the server proxy (Gemini primary, OpenRouter fallback) → anything case-specific is directed to the contact form or phone → requests for legal advice are refused, and the refusal is logged for review.
- **AI assistant — voice (new in v2, ADR-004):** visitor taps the voice control → a consent notice appears first, then the browser microphone permission → the server mints an ephemeral Gemini Live token (the paid key stays server-side) → real-time speech conversation under the same scope as chat → the session ends at its duration or turn cap with a contact CTA → the transcript is stored in `ai_conversations` only where consent was recorded, under the retention policy with auto-delete.

## 3. Architecture & Tech Stack

*Source: CODING_STANDARDS.md; ADR-002; ADR-003 (email); ADR-004 (AI layer); arnaud-cheynut/specs/design-system.md; PROJECT-SUMMARY.md.*

- **Frontend:** Next.js 15 (App Router exclusively, no `pages/`), TypeScript strict, Tailwind CSS + shadcn/ui. Server Components by default; `"use client"` only where state or DOM events require it (contact form, carousel controls, mobile menu). Design tokens come from `arnaud-cheynut/specs/design-system.md` (navy/gold, Fraunces/Inter) as implemented by the UI Designer's `DESIGN.md` (TASK-003).
- **Backend:** Supabase Postgres with RLS enabled on every table. Supabase Storage (private bucket) for form attachments. Supabase Auth is part of the stack standard but has no role in the MVP: the site exposes no login, and content authoring happens in Supabase Studio under the lawyer's account. Edge Functions only if a webhook or scheduled job needs one (e.g., retention cleanup).
- **AI layer (new in v2, ADR-004):** dual-mode assistant. Voice runs over the Gemini Live API WebSocket with ephemeral tokens minted server-side, so the paid key never reaches the browser bundle. Chat streams from a Next.js server proxy route (Gemini `generateContent` streaming) with OpenRouter chat completions (SSE) as the fallback. Rate limiting per IP and per session, plus session duration caps, bound cost and abuse. The assistant scope is enforced server-side where possible — office information, navigation, practice-area summaries, process explanations — and it refuses legal advice of any kind.
- **Email:** transactional notifications for every user-initiated process — form receipt and lawyer notification at launch, process-triggered emails added as features land (ADR-003). Resend is the default transport; SMTP via nodemailer is the documented swap-in for an existing provider. Supabase built-in email covers auth templates only. Newsletter automation is Phase 2.
- **Analytics:** Vercel Analytics or Plausible (cookieless). This keeps the site free of a consent banner; if GA4 or ad pixels are ever required, a consent management platform becomes mandatory first.
- **Infrastructure:** Vercel, strictly. Preview deployments per pull request. Static/ISR-first rendering for all marketing pages so content survives a Supabase outage. Cloudflare DNS optional.
- **Key Dependencies:** zod (validation), next-intl (locale routing, FR default + EN, geo-detected with cookie persistence), @supabase/ssr + @supabase/supabase-js, resend, lucide-react (icons), plus the AI SDKs (Gemini Live browser SDK, OpenRouter client) once the Researcher verifies current API signatures (ADR-004). The Researcher confirms exact versions before install; other heavyweight dependencies require Human approval (AGENTS.md rule 12).
- **Content authoring surface:** Supabase Studio. A short training session and a written runbook for the lawyer are part of the handoff. A custom admin UI is Phase 2 if Studio proves awkward for daily use.

## 4. Edge Cases & Error Handling

*Source: content-strategy.md §3.4, §7.1; assets-checklist.md; competitor-analysis.md; ADR-003; ADR-004.*

| Scenario | Expected System Behavior |
|----------|--------------------------|
| Bot or spam form submission | Honeypot field + submit-timing check + server-side rate limiting (per IP, per email); Zod validation server-side. Cloudflare Turnstile added later if observed spam justifies it. Rejected submissions leave no success state. |
| Duplicate submission (double-click, retry) | Submit button disabled while the Server Action is pending; duplicate inserts suppressed on (email, subject) within a short window so the lawyer sees one lead. |
| Attachment oversized or wrong type | Client-side check (10 MB max, PDF/DOC/JPG, content-strategy.md §3.4) repeated server-side; clear non-technical error message; executables rejected outright. |
| Attachment contains sensitive legal data | Stored in a private Supabase Storage bucket with RLS; access only via short-lived signed URLs for the lawyer; auto-delete after a retention window agreed with the DBA (data minimization). |
| Supabase unreachable | Marketing pages are prerendered (static/ISR) and keep serving from the Vercel edge; contact details render server-side as static content, so phone and email stay visible; the form shows a generic error and points at the phone number. |
| Email delivery fails (either transport) | The lead is never lost: the row is persisted in `contact_submissions` before the email step; failures are logged and visible in Supabase Studio for manual follow-up. Email is the notification, the database is the source of truth. |
| Stale content | Every content page displays a "Mis à jour le" date; content unreviewed for 12+ months is flagged to the lawyer (quarterly review cadence, content-strategy.md §7.1). |
| GDPR data subject request | Documented deletion/export procedure in the privacy policy; retention policy covers form rows and attachments; a named contact (the lawyer or his designee) handles requests. |
| Missing EN translation (FR default for non-matched locales) | next-intl falls back to the FR version with a visible locale notice rather than a 404. |
| Unknown URL | Custom 404 with navigation back to Accueil and Contact. |
| Legal page outdated after a law change | Legal pages carry review dates; annual review plus event-driven review when Monaco law changes (content-strategy.md §7.1). |
| Voice session cap exceeded | The session ends gracefully with a closing message and a contact CTA (form or phone); the visitor may start a new session subject to rate limits (ADR-004). |
| Gemini API unavailable | Chat falls back to OpenRouter (SSE streaming); if the voice channel fails, the assistant degrades to chat-only with a visible notice. The widget stays usable in both cases. |
| Prompt injection attempt | Scope enforcement lives in the server-side system prompt; the assistant exposes no tool-calling to hijack; legal-advice extraction and role-override attempts are refused and logged for review (ADR-004). |
| Voice consent declined | Voice mode stays off and nothing is captured; the visitor can still use chat mode. |
| Transcript retention expired | Auto-delete runs on `expires_at` per the retention window agreed with the DBA; the privacy policy documents the deletion procedure. |
| Email transport misconfigured | Missing or invalid email credentials surface through `env-check.sh` parity; the lead still persists in `contact_submissions` before any email step (ADR-003); the failure is logged and admin-visible in Supabase Studio for manual follow-up. |

## 5. Non-Functional Requirements

*Source: PROJECT-SUMMARY.md (performance budgets); profile-master.md §6; competitor-analysis.md §3.*

- **Performance:** LCP < 2.0s, INP < 200ms, CLS < 0.1; Lighthouse 90+ across all categories; JS budget < 170 KB gzipped. Static-first rendering makes this reachable without heroics.
- **Security:** RLS enabled and deny-by-default on all tables (public reads only where `published = true`); server-side Zod validation on every input; rate limiting on the contact form and the AI assistant endpoints; secrets only in environment variables, never committed; private Storage buckets; Security Agent review (OWASP) before launch.
- **Scale:** Traffic is modest by design — the target is 500+ visits/month at month 6 for a solo practice. Vercel and Supabase entry tiers absorb that many times over. The binding constraint is one lawyer's calendar, so the site optimizes for lead quality (screened, informed prospects) over volume.
- **Accessibility:** WCAG 2.1 AA (contrast 4.5:1 text / 3:1 UI, visible focus states, keyboard navigation, alt text, reduced motion, logical heading order). If the testimonial carousel auto-rotates, it needs a visible pause control (WCAG 2.2.2).
- **Availability:** static-first architecture keeps marketing content online even when Supabase or the form pipeline is down; the emergency phone number never depends on JavaScript or a backend.
- **AI assistant (new in v2, ADR-004):** voice first response < 1s; chat first token < 2s; API cost ceilings apply — session duration caps, per-IP/per-session rate limits, and provider dashboard monitoring keep spend within the budget approved at OQ 4; refusal behavior and disclaimer wording are reviewed with Me Cheynut before launch (§10).

3. **Persistent site-wide 24/7 emergency CTA.** Competitors bury urgency or omit it (§3 gap 8). A tap-to-call banner on every page targets the "avocat urgence Monaco" and "garde à vue Monaco" quick wins (§6.1).
4. **Monaco-specific legal content library.** Actualités citing the Journal de Monaco and Legimonaco, written for Monégasque procedure. Competitors publish generic French-law content at best (§7.2 content moats).
5. **Personal brand depth.** The audited market is firm-branded (CMS, 99avocats, Zabaldano, PBLB) or thin (Marquet) (§2). Deep bio, philosophy, network, and publications pages occupy the quadrant nobody claims (§4: high personal touch + high digital maturity).
6. **Verifiable trust signals.** Bar registration number, RCP insurance mention, formation continue. Competitors use generic badges (§3 gap 10).
7. **Professional multilingual coverage.** Only CMS Law is multilingual in the audit; local firms are FR-only or machine-translated (§5). A solo with real FR/EN stands apart — Human decision: FR + EN at launch; IT stays Phase 2.
8. **Performance discipline.** Static-first, <2s LCP, 90+ Lighthouse. PBLB and Marquet-tier sites are slow or broken on mobile (§2 audits); this matches the best competitors and beats the rest.
9. **Accessibility as a stated feature.** WCAG 2.1 AA; all five audited competitors ignore or only partially meet it (§3 gap 7).
10. **Print-optimized pages.** For client meeting prep; nobody in the audit offers it (design-system.md §13).
11. **Cookieless analytics.** Privacy-first measurement with no consent banner (§7.3 technical moats).
12. **AI assistant (voice + chat).** A dual-mode site assistant scoped to administrative help, with a strict refusal of legal advice (ADR-004). No audited Monaco competitor offers voice interaction on a law firm site.

## 10. Compliance Requirements

*Source: profile-master.md §8; assets-checklist.md; design-system.md §14; content-strategy.md §7; ADR-004 (AI assistant).*

- **Monaco Bar advertising rules (Ordre des Avocats de Monaco).** Advertising by avocats is restricted under deontological rules. Before launch, Me Cheynut confirms what is permitted: client testimonials, published fee ranges, "urgence 24/7" wording, anonymized case studies (OQ 2). All public copy carries his explicit sign-off, and he bears deontological responsibility for the site's content. The site presents his personal brand; the Zabaldano affiliation appears only as factually accurate contact data, with nothing implying a partnership structure beyond reality.
- **Data protection (RGPD + Monaco Law No. 1.165).** Monaco's Law No. 1.165 (2018) governs personal data under CCIN supervision, and RGPD obligations apply to EU visitors. Requirements: privacy policy, cookie policy, required consent checkbox on the form, data minimization (attachment retention window), a data subject rights procedure with a named contact, and a processing register. Verify with the lawyer whether an EU representative (GDPR Art. 27) is needed for Monaco-based processing aimed at EU data subjects.
- **AI assistant deontological framing (new in v2, ADR-004).** The assistant presents itself as administrative help: every session opens with a disclaimer stating it covers office information, navigation, and process explanations, and that legal advice comes from Me Cheynut alone. The disclaimer wording and the assistant system prompt carry his sign-off before launch, and refusal behavior is reviewed with him (§5).
- **Voice consent (RGPD + Monaco Law No. 1.165).** Voice capture is personal-data processing: a consent notice precedes any microphone access, transcripts are stored only where consent was recorded, the retention window is set with the DBA, and the privacy policy documents the voice data flow and its deletion procedure.
- **Mentions légales.** Publisher identity (name, professional title, bar, address, contact), hosting provider (Vercel), intellectual property notice, editorial responsibility. Required by Monégasque/French practice.
- **WCAG 2.1 AA.** Per design-system.md §14: contrast ratios (4.5:1 text, 3:1 UI), visible focus states, keyboard navigation, alt text, reduced motion, logical heading hierarchy, associated form labels, skip link, ARIA landmarks.
- **RCP insurance.** Verify the certificate and display the mention (assets-checklist.md).
- **LCB/FT (anti-money laundering).** An onboarding matter for the practice itself, outside the website's scope; noted here to prevent accidental scope creep.

## 11. Out of Scope

Explicit exclusions for this project:

- **Client portal / secure document exchange / case status tracking.** Listed as a Phase 2 candidate in the research, but it amounts to a separate project: its own security review, auth flows, RLS design, and a maintenance commitment a solo practice may not want to carry. Revisit after launch if at all.
- **Payment processing / online fee payment.** Fee discussions happen offline; no payment rails on the site.
- **Sanity.io or any external CMS.** Locked by Human decision (ADR-002): content lives in Supabase tables managed through Studio.
- **E-commerce or any transactional functionality.**
- **Custom admin UI in the MVP.** Supabase Studio is the authoring surface; a custom admin is Phase 2 only if Studio proves awkward.
- **PWA / offline mode.** No user story supports it.
- **Dark mode as an MVP acceptance criterion.** The UI Designer may ship it as polish; the MVP passes without it.
- **AI legal advice of any kind.** The v1 exclusion of live chat / chatbots is superseded by the Human-approved AI assistant (ADR-004): the assistant provides administrative help with a strict refusal of legal advice. What stays out of scope is AI-dispensed legal guidance — case-specific advice, document interpretation, strategy recommendations — which only Me Cheynut may provide.
- **Webinar or event registration.**
- **Google Ads / paid campaign management.** Marketing activity outside the website's scope.
- **Video production in the MVP.** Phase 2 per assets-checklist.md.
